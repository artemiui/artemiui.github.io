## Overview

This project is a discrete-event microscopic transit simulation modeled after the 24-station Epifanio de los Santos Avenue (EDSA) Busway Bus Rapid Transit (BRT) corridor in Metro Manila, Philippines. The engine simulates multi-berth median station contention, bidirectional passenger flows, vehicle kinematics, rogue dwelling behavior, and corridor-level shockwave propagation.

The simulation runtime is implemented in Python using `SimPy` for process-oriented discrete-event modeling and `NumPy` for stochastic distributions. The web client renders dynamic telemetry via dual synchronized topological representations: a calibrated geometric route schematic and a dual-ring concentric circulation carousel.

---

## Demand Modeling & Passenger Generation

Passenger arrivals at each station $i \in \{1, \dots, 24\}$ follow an inhomogeneous Poisson process:

$$N_i(t, t + \Delta t) \sim \text{Poisson}\left(\lambda_i(t) \cdot \Delta t\right)$$

where the time-varying arrival rate $\lambda_i(t)$ is defined as:

$$\lambda_i(t) = \lambda_{i, \text{base}} \cdot M_i(t)$$

- $\lambda_{i, \text{base}}$: Baseline passenger arrival rate per minute calibrated to station capacity and historical passenger volumes.
- $M_i(t)$: Dynamic rush-hour multiplier corresponding to simulated time of day $t$.

### Directional Origin-Destination (OD) Matrix

Upon arrival, each passenger is assigned a destination station $j \neq i$ via a time-dependent discrete probability distribution:

$$P(D = j \mid O = i, t) = \frac{W_{ij}(t)}{\sum_{k \neq i} W_{ik}(t)}$$

The attraction weights $W_{ij}(t)$ model asymmetric commuter flow patterns in Metro Manila:
- **Morning Peak ($07:00 \le t < 09:30$):** Inflow predominantly southbound toward major Central Business Districts (Ortigas, Buendia, One Ayala) with directional bias factor $\gamma_{\text{SB}} \approx 3.5 \times 2.5$.
- **Evening Peak ($17:00 \le t < 20:00$):** Outflow predominantly northbound toward residential terminal hubs (Fernando Poe Jr., Balintawak, Monumento) with directional bias factor $\gamma_{\text{NB}} \approx 3.5 \times 2.5$.
- **Midday Peak ($11:30 \le t < 13:30$):** Commercial centroid attraction (SM North EDSA, Trinoma) with multiplier $\gamma_{\text{mid}} \approx 4.0$.

Each passenger is queued in the dedicated directional platform buffer: $\mathcal{Q}_{i, \text{forward}}$ (Southbound) or $\mathcal{Q}_{i, \text{reverse}}$ (Northbound).

## Bus Motion, Kinematics, and Network Geometry

The transit corridor spans $23.8\,\text{km}$ along EDSA. Inter-station link travel times are computed from OpenStreetMap highway segments:

$$T_{\text{travel}}(i \to i+1) = \frac{d(i, i+1)}{v_{\text{lane}}} + \delta_{\text{U-turn}}$$

- $d(i, i+1)$: Geodesic path distance between station nodes along the dedicated median lane.
- $v_{\text{lane}}$: Mean operating speed within the busway, regulated by speed limits ($35\text{--}50\,\text{km/h}$).
- $\delta_{\text{U-turn}}$: Stochastic operational delay modeling Bagong Barrio surface turning conflicts:
  $$\delta_{\text{U-turn}} \sim \begin{cases} U(45\,\text{s}, 150\,\text{s}) & \text{with probability } p_{\text{u-turn}} = 0.25 \\ 0 & \text{otherwise} \end{cases}$$

## Multi-Berth Queueing & Platform Dwell Dynamics

### Berth Resource Contention

Each station platform $i$ features $c_{i}$ dedicated physical berths per direction, modeled as a finite multi-server queuing resource $M/G/c_{i}$. When bus $b$ arrives at station $i$, it must acquire an unoccupied berth:

$$\text{Delay}_{\text{berth}}(b, i) = t_{\text{docking}} - t_{\text{arrival}}$$

If all $c_i$ berths are occupied, incoming buses form an upstream physical queue:

$$L_{\text{queue}} = N_{\text{queued}} \cdot L_{\text{bus}}$$

where $L_{\text{bus}} = 12.0\,\text{meters}$. Upstream backups exceeding $150\,\text{meters}$ produce bottleneck shockwaves that block intermediate lane progression.

### Dwell Time Formulation

Dwell times follow the Transit Capacity and Quality of Service Manual (TCQSM) standard, incorporating passenger exchange volumes, door actuation overhead, and interior crowd friction:

$$T_{\text{dwell}} = \begin{cases} 0 & \text{if } N_{\text{on}} = 0 \land N_{\text{off}} = 0 \land \neg \text{Terminal} \\ T_{\text{overhead}} + \max\left(N_{\text{on}} \cdot t_{\text{board}}, N_{\text{off}} \cdot t_{\text{alight}}\right) & \text{otherwise} \end{cases}$$

Where:
- $T_{\text{overhead}} = 4.0\,\text{s}$ (door opening, driver clearance, closing).
- $N_{\text{off}}$: Passengers whose destination matches station $i$.
- $N_{\text{on}} = \min\left(\text{Capacity} - \text{Occupancy}, |\mathcal{Q}_{i, \text{dir}}|\right)$.
- Interior crowd friction factor:
  $$t_{\text{board}} = t_{\text{board}, 0} \cdot \left(1 + 0.45 \cdot \left(\frac{\text{Occupancy}}{\text{Capacity}}\right)^2\right) \cdot \xi_{\text{board}}$$
  with $t_{\text{board}, 0} = 2.5\,\text{s/pax}$ and $\xi_{\text{board}} \sim U(0.92, 1.15)$.
- $t_{\text{alight}} = 1.5\,\text{s/pax} \cdot \xi_{\text{alight}}$ with $\xi_{\text{alight}} \sim U(0.90, 1.10)$.

### Zero-Demand Free-Flow Condition

To prevent artificial clogging on underutilized segments, if $N_{\text{on}} = 0$, $N_{\text{off}} = 0$, and the station is not a designated terminal turnaround, the bus bypasses the berth resource request entirely:

$$T_{\text{dwell}} = 0, \quad \text{Delay}_{\text{berth}} = 0$$

## Rogue Actor Lingering Dynamics ("Nagpupuno")

In unregulated or semi-formal dispatch regimes, drivers occasionally linger at high-demand platforms to maximize fare revenue before departing:

$$\text{Condition: } \left(\frac{\text{Occupancy}}{\text{Capacity}} < 0.90\right) \land \left(|\mathcal{Q}_{i, \text{dir}}| > 0\right) \land (i < \text{Terminal})$$

When the condition holds, lingering occurs with probability:

$$P_{\text{rogue}} = p_{\text{base}} \cdot \mathbf{1}_{\text{hotspot}} \cdot 1.3$$

The additional obstruction dwell is drawn from:

$$T_{\text{rogue}} \sim U(60\,\text{s}, 180\,\text{s})$$

During $T_{\text{rogue}}$, the bus retains berth ownership, directly delaying downstream buses waiting in the physical queue and propagating localized headways:

$$h_{\text{actual}} = h_{\text{scheduled}} + T_{\text{rogue}} + \sum \text{Delay}_{\text{berth}}$$

---

## Terminal Turnaround & Stacking Capacity

Terminals at Monumento and PITX are modeled as bounded staging facilities:

$$\text{Capacity}_{\text{stage}} = 15 \text{ vehicles}$$

Upon arrival at the terminal berth, all remaining passengers alight ($N_{\text{off}} = \text{Occupancy}$). Buses then enter the terminal staging pool for mandatory layover and route turnaround:

$$T_{\text{turnaround}} = 300\,\text{s} \quad (5.0\,\text{minutes})$$

Once turnaround completes, the vehicle swaps directional orientation ($\text{forward} \leftrightarrow \text{reverse}$) and enters the terminal dispatch queue.

## Telemetry Extraction & Data Structure

The simulation loop captures system-wide state snapshots at uniform sampling intervals $\Delta \tau = 2.0\,\text{minutes}$:

$$\mathcal{S}_k = \left(t_k, \mathbf{P}_k, \mathbf{B}_k, \mathbf{Q}_k\right)$$

- $t_k$: Simulation clock timestamp.
- $\mathbf{P}_k = \sum_{i=1}^{24} |\mathcal{Q}_i(t_k)|$: Total waiting passenger count corridor-wide.
- $\mathbf{B}_k$: Vector of active bus states (spatial coordinates, instantaneous velocity, passenger load, active delay).
- $\mathbf{Q}_k$: Per-station multi-berth queue metrics:
  $$\mathbf{q}_{i}(t_k) = \left(|\mathcal{Q}_{i, \text{SB}}|, |\mathcal{Q}_{i, \text{NB}}|, N_{\text{bus, queued}}, \bar{d}_{\text{delay}}, \mathbf{1}_{\text{rogue}}\right)$$

### Export Data Schema

The front-end client exports this dataset as a structured JSON payload for external econometric and operations research tools:
- `simulation_configuration`: Global parameters ($h_{\text{dispatch}}$, fleet size $N_{\text{fleet}}$, vehicle capacity, $p_{\text{rogue}}$, observation bounds).
- `corridor_telemetry_summary`: Global extremes ($\max \mathbf{P}_k$, peak bus queue, maximum delay timestamp, primary bottleneck node).
- `stations_summary`: Aggregated station performance indicators (peak queue, average platform wait, rogue occurrence frequency).
- `telemetry_snapshots`: Comprehensive sequential time-slices for external visualization and time-series modeling.

Constructed with `StationQueue(station_def: StationDefinition)`. The `berth_resource` field is set to a `simpy.Resource` during engine initialization — it is **not** set in the constructor.

Key method — `board_to_bus`:
```python
def board_to_bus(self, bus, dwell_config, alighting_fraction_range, rng, sim_time)
    -> tuple[int, int, float]   # (n_boarded, n_alighted, dwell_time)
```
Dwell formula: `T_dwell = door_overhead_sec + max(n_on × boarding_time_per_pax_sec, n_off × alighting_time_per_pax_sec)`

**Denial tracking**: after boarding, if the bus is full and passengers remain in queue, `total_passengers_denied` is incremented by the remaining queue length.

Abstract base class for runtime scenario injection:

Subclass this to implement bus breakdowns, express services, or holding strategies. Register instances via `sim_state.interventions.append(my_intervention)`.

### `engine.py` — SimPy Processes

#### Process: `passenger_generator(env, sim_state, rng)`

Runs in an infinite loop, batching every 60 simulation-seconds. For each station:
1. Computes current `rush_multiplier` via `_get_rush_multiplier(sim_hour, station_name, config)`.
2. Draws `n_arrivals ~ Poisson(base_rate × multiplier)`.
3. Each passenger gets a weighted-random destination (3× weight for major hubs).
4. Logs `QUEUE_UPDATE` events to `sim_state.event_log`.

#### Process: `bus_process(env, bus, sim_state, network, rng)`

Full bus lifecycle in an infinite loop:
1. Gets station sequence for current `bus.direction`.
2. For each station (skipping travel for the first station of a trip):
   - **Travel**: `yield env.timeout(travel_time)` with `bus.state = EN_ROUTE`.
   - **Queue for berth**: `with station_queue.berth_resource.request() as req: yield req` — tracks queue delay.
   - **Dwell**: Calls `station_queue.board_to_bus(...)`, yields `env.timeout(dwell_time)`.
   - Records `BUS_ARRIVE_STATION`, `BUS_DEPART_STATION` events with occupancy/delay details.
3. At terminal: alight all passengers, 300s turnaround, reverse direction, increment `trip_count`.

#### Process: `bus_dispatcher(env, sim_state, network, rng)`

Dispatches buses alternating forward/reverse at `dispatch_interval_seconds` until `fleet_size` is reached. Each bus gets its own `bus_process` coroutine.

#### Entry Point: `run_simulation(config, network) → SimulationState`

Creates `simpy.Environment`, initializes all `StationQueue` objects with `simpy.Resource(env, capacity=berth_capacity)`, seeds `np.random.default_rng(config.random_seed)`, starts `passenger_generator` + `bus_dispatcher`, and runs `env.run(until=duration_hours × 3600)`.

## Simulation Model Details

### Passenger Arrival Model

Non-homogeneous Poisson process. Every 60 simulation-seconds, for each station:

```
λ(t, station) = base_passenger_arrival_rate × rush_multiplier(station, hour(t))
n_arrivals ~ Poisson(λ)
```

- **Off-peak**: `λ = 2.0` pax/min (default)
- **Rush hour at major hub**: `λ = 2.0 × 4.0 = 8.0` pax/min
- **Rush hour at local stop**: `λ = 2.0 × 1.5 = 3.0` pax/min

### Dwell Time Formula

```
T_dwell = T_overhead + max(N_on × t_board, N_off × t_alight)
```

Default: `T_dwell = 10 + max(N_on × 2.5, N_off × 1.5)` seconds.

Boarding and alighting happen in parallel (max, not sum), which models multiple-door buses.

### Alighting Model

At each intermediate stop, a fraction `f ~ Uniform(0.05, 0.30)` of on-board passengers alight. At terminal stations (Monumento, PITX), **all** passengers alight.

### Station Berthing

Each station has a `simpy.Resource(capacity=berth_capacity)`. When a bus arrives:
1. It requests a berth slot.
2. If all berths are occupied, the bus waits (simulating physical queuing in the busway lane).
3. Queue delay is tracked in `station_queue.cumulative_bus_delay_sec`.
4. Overtaking is disabled by default (`config.enable_overtaking = False`) — buses process berth requests sequentially.

### Travel Time

```
T_travel = distance_meters / (bus_lane_speed_limit_kmh × 1000 / 3600)
```

Default: 50 km/h → 13.89 m/s. With haversine fallback, total route ≈ 37.2 km, so end-to-end free-flow time ≈ 44.6 minutes.

## How to Extend

### Adding a New Station

Edit `get_default_config()` in `config.py`. Insert a new `StationDefinition` into the `stations` list at the correct geographic position. Add its name to `rush_hour_multipliers` if it's a major hub.

### Changing Demand Patterns

Modify `DemandConfig` fields:
- Add new `RushHourWindow` entries for midday or late-night peaks.
- Adjust `base_passenger_arrival_rate` for system-wide throughput.
- Set per-station multipliers in `rush_hour_multipliers`.

### Implementing an Intervention

Subclass `InterventionEngine` from `entities.py`:

```python
from edsa_carousel_sim.entities import InterventionEngine

class BusBreakdown(InterventionEngine):
    def trigger(self, env, sim_state, event_type, **kwargs):
        if event_type == "breakdown":
            bus_id = kwargs["bus_id"]
            bus = sim_state.buses[bus_id]
            bus.state = BusState.BROKEN_DOWN
            # Block lane for repair_time seconds
            yield env.timeout(kwargs.get("repair_time", 600))
            bus.state = BusState.IDLE
```

Register it before running: `sim_state.interventions.append(BusBreakdown())`.

## Event Log Schema

Events in `sim_state.event_log` follow this structure:

```python
{
    "time": float,          # SimPy timestamp (seconds from sim start)
    "event_type": str,      # One of the types below
    "entity_id": str,       # Bus ID (as string) or station name
    "details": dict         # Event-specific payload
}
```

| `event_type` | `entity_id` | `details` keys |
|-------------|-------------|----------------|
| `BUS_DISPATCH` | bus ID | `direction` |
| `BUS_ARRIVE_STATION` | bus ID | `station`, `occupancy` |
| `BUS_DEPART_STATION` | bus ID | `station`, `boarded`, `alighted`, `delay_sec` |
| `TRIP_COMPLETE` | bus ID | `direction`, `trip` |
| `QUEUE_UPDATE` | station name | `queue_length`, `arrivals` |

## Dependencies

| Package | Required | Purpose |
|---------|----------|---------|
| `simpy >= 4.0` | **Yes** | Discrete-event simulation engine |
| `numpy >= 1.24` | **Yes** | Random number generation, array operations |
| `pandas >= 2.0` | **Yes** | DataFrame exports for metrics |
| `matplotlib >= 3.7` | Optional | Static chart generation |
| `seaborn >= 0.12` | Optional | Chart styling |
| `folium >= 0.14` | Optional | Interactive HTML map |
| `networkx >= 3.1` | Optional | Graph shortest-path computation |
| `osmnx >= 1.6` | Optional | OpenStreetMap network download |
| `geopandas >= 0.13` | Optional | Required by osmnx |
| `shapely >= 2.0` | Optional | Required by osmnx |

The simulation runs correctly with only `simpy`, `numpy`, and `pandas`. All visualization and GIS features degrade gracefully when their dependencies are missing.
